# Handoff 0016 — AGPL-3.0 relicensing, 0.1.1, and open-source readiness

**Branch:** `phase-agpl-oss-readiness`
**Date:** 2026-09-30

## What changed

AuraSpend moved from Apache-2.0 to **AGPL-3.0-or-later**, and was cut as 0.1.1.
The driver was one specific gap: under Apache-2.0, someone can fork AuraSpend into
a hosted proprietary service and never publish their changes. AGPL-3.0 §13 closes
that. Full reasoning, including what the change does *not* buy, is in
[ADR 0009](../adr/0009-agpl-3.0-relicensing.md).

Two things were settled before any code was touched:

- **Relicensing is legal and clean.** `git log --all --format='%aN'` shows exactly
  one human copyright holder (84 commits); the rest are Dependabot and a local
  agent identity. No CLA was needed retroactively, and no contributor had to be
  chased for consent.
- **`.github/private/` is untracked, not published.** See §3.

## Decisions

1. **AGPL-3.0-*or-later***, not `-only`. It costs nothing and means a future FSF
   revision does not force another relicensing decision.
2. **Prospective only.** Releases ≤ 0.1.0 stay Apache-2.0, and `docs/terms.html`
   records that explicitly.
3. **A CLA with copyright assignment is now required** (ADR 0009, `CONTRIBUTING.md`,
   the PR template). This is the one genuinely new obligation, not a trade-off:
   the 0.1.1 switch was possible *only* because there was a single copyright
   holder, and that stops being true at the first external PR.
4. **Historical records annotated, never rewritten.** ADR 0001 and ADR 0007 still
   say Apache-2.0 where they were written, with a pointer to 0009. Rewriting a
   past decision to match the present is how an ADR log stops being trustworthy.
5. **Third-party licences left alone, deliberately.** Every "Apache-2.0" that
   refers to a dependency is correct: the bundled font is OFL, ONNX Runtime is
   MIT, Lottie/AndroidX/the Google libraries are Apache-2.0, and the
   runtime-downloaded `all-MiniLM-L6-v2` is Apache-2.0. A global find-and-replace
   would have made false licensing claims about third parties. This is recorded as
   `AGENTS.md` rule 9 so the next agent does not "helpfully" fix it.

### Two bugs the verification caught

- **`AuraCard` shrink-wrapped inside a `LazyColumn`.** It honours the caller's
  modifier and does not force a width, so each component card sized to its own
  text. Found by looking at a device screenshot, fixed with explicit
  `fillMaxWidth()` at the call sites — *not* by changing `AuraCard` to always
  fill, which would break cards that intentionally size to content.
- **Two lint errors in the new screen**, both real and both fixed rather than
  suppressed: `LocalContext.current.resources` is not configuration-aware (→ use
  `LocalResources.current`), and `Uri.parse` should be the KTX `String.toUri`.

### Two bugs in `tools/check_license.sh` itself

Worth recording, because both were found by asking "can this check still *fail*?"
rather than "does it pass?":

- **The whole check was silently inert.** POSIX awk has no `/i` case-insensitive
  flag — `/re/i` parses as division, `($0 ~ /re/) / i`, and since `i` is 0 then
  `1/0` is truthy, so *every* line matched and every comparison section was
  treated as exempt. Now uses `tolower()`.
- **Shell comments were parsed as headings.** `/^#+[[:space:]]/` matches the
  `#` in a commented command inside a fenced code block, so the build examples in
  the README set flags at nonsense places. Fence state is now tracked explicitly.

Same family of trap as the `grep -E '\b'` note in `AGENTS.md`: a regex that
silently means something other than what you intended. Three negative tests now
guard it — injecting a stale Apache claim into a normal section, appending one at
EOF, and reverting `LICENSE` all correctly fail.

The check's first draft also produced two false positives, on lines that were
both *correct*: the sentence describing the model's licence, and the historical
note that AuraSpend was Apache-2.0 up to 0.1.0. Rather than loosen the patterns, it
is now section-aware (a licence-comparison section is exempt as a unit, with
level-aware heading detection) and a failure prints the offending line, because
"it failed" is not actionable.

  `buglist.md` against the code before discarding it — all five are addressed:
  theme switching exists (`AppThemeMode` / `currentTheme`); category management

  render as empty sponsor buttons.
- **`CHANGELOG.md`** created at root in Keep a Changelog format. The old

- **README** gained Code of Conduct, Support, Changelog, Roadmap, and
  Acknowledgements sections; all 27 relative links verified to resolve.

## In-app changes

New `Settings → About → Open-source licenses` screen, with two panes via
`AuraSegmentedControl`:

- **Components** — AuraSpend's own AGPL grant, a link to the source, and a
  third-party table. The list is hard-coded on purpose: an out-of-date
  attribution is a licence-compliance bug, and nothing else in the build would
  notice. `tools/check_license.sh` fails CI if a dependency is added without a
  row.
- **License text** — the verbatim AGPL-3.0 text, read from `res/raw`. Two panes
  rather than one long page because the text is ~34 KB and nesting a scrollable
  text block inside a `LazyColumn` produces a gesture conflict where neither
  scroll responds reliably.

The splash footer was hardcoded English (`"Open source · Apache-2.0"`), which
violated the project's own i18n rule. It is now `R.string.splash_open_source_license`
with a Hindi twin.

The About version string was hardcoded, which is how it drifted once already
(a changelog said 0.2.1, the app said 0.1.0). It now reads
`BuildConfig.VERSION_NAME`.

## Open risks

1. **The AGPL switch is irreversible for this code.** Dual licensing or a
   commercial exception can be added later; going back to permissive cannot. This
   is stated in ADR 0009 rather than left implicit.
2. **CI has still never run on any of this.** `ci.yml` fires on push/PR to
   `main`; this branch is not `main`, and there is no PR open. `check_license.sh`
   passes locally (and its negative tests were verified), but the *workflow* edit
   — adding the step to `ci.yml` — is unexercised.
3. **The release build is unsigned.** `app-free-release-unsigned.apk` needs
   `secrets.properties` with the keystore. The user's `auraspend.jks` exists
   locally and is correctly gitignored.
4. **`versionCode` 1 → 2** is required for the Play upload; it is set, but the
   Play release itself is blocked on (3).
5. **Play Store listing metadata and the Data Safety form live outside the repo.**
   The no-telemetry claim there must match reality — the runtime graph was
   resolved and contains no analytics, ads, or crash-reporting SDK, so the claim
   holds, but the form itself has to be updated by hand.
6. **The in-app license pane was verified on a debug build on a moto g40
   (Android 12).** The release build ships the text (sha256-verified) but was not
   launched on-device.
